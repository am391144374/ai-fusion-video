# ComfyUI 输出媒体类型识别修复设计

## 问题背景

ComfyUI 的 `SaveVideo` 节点已经成功生成 MP4 文件，但 Jobs API 将文件描述放在 `outputs.<nodeId>.images` 数组中。当前后端优先根据数组字段名判断媒体类型，因此把 `.mp4` 误判为图片；当输出绑定要求 `video` 时，该文件会被过滤，最终提示“绑定的输出节点没有返回文件”。

## 方案比较

1. 将输出绑定改成 `image`：改动最小，但会让视频以图片语义存储，目录和后续处理均不正确，不采用。
2. 针对 `SaveVideo` 或节点 `92` 特判：可以解决当前工作流，但依赖节点类型或编号，无法覆盖其他同类自定义节点，不采用。
3. 优先根据文件扩展名和 `format` 判断，最后才使用输出数组字段名：与文件真实类型一致，兼容 ComfyUI 将视频放入 `images` 数组的返回方式，采用此方案。

## 设计

只调整 `ComfyUiOutputResolver` 的媒体类型识别顺序，不改变接口、数据库、前端配置或输出绑定结构。

识别顺序如下：

1. 根据 `format` 的 MIME 类型识别图片、视频或音频。
2. 根据 `filename` 的扩展名识别图片、视频或音频。
3. 当前两项均无法判断时，再根据输出数组字段名识别。
4. 都无法识别时保持为通用文件 `file`。

因此，字段名为 `images`、文件名为 `.mp4` 时应识别为 `video`；普通 `.png` 图片仍识别为 `image`。

## 错误处理和兼容范围

- 继续要求文件描述包含 `filename`、`subfolder`、`type`。
- 继续只解析显式绑定的输出节点。
- 继续按照绑定媒体类型过滤输出，避免把不匹配的文件保存到错误目录。
- 不针对单个工作流、节点编号或节点类写特殊分支。

## 验证标准

- 新增测试：`images` 数组中的 `.mp4` 文件能够匹配 `video` 输出绑定。
- 保留并通过现有图片、视频、音频、通用文件和异常结构测试。
- 相关代码完成编译和定向单元测试。
